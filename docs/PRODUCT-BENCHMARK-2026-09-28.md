# Learning OS benchmark · 2026-09-28

## 评估标准

不比较功能数量，只比较用户能否更快完成三件事：确认下一步、找到课程资料、从知识点继续复习。

## GitHub 样本与启发

| 项目 | 值得借鉴 | 对 MBA Learning OS 的取舍 |
| --- | --- | --- |
| MoodleTasks | Upcoming / Overdue / Done 分流、紧急程度颜色、置顶和提醒 | Deadline 默认聚焦“逾期 + 未来 7 天”，完整列表退居二级筛选 |
| Neoma | Today / Upcoming 学习工作台、统一搜索、本地优先、知识关系图 | 首页改成行动简报；保留本地优先，不为基础体验引入付费云依赖 |
| Dotstell | 图谱、反向链接、任务优先级与全局搜索在同一工作台 | Map 搜索扩展到框架、案例和笔记正文；后续再补显式跨课程链接 |
| OpenTutor | 资料块、知识图谱、带来源的学习辅助和学习计划 | 保留“资料来源可追溯”；暂不加入泛化 AI 对话，避免遮蔽核心信息 |
| Obsidian Learning Engine | 前置知识关系、按状态排序的学习队列、错误复盘 | 可作为后续复习队列方向；当前先把真实课程、Deadline 与资料入口做好 |

## 当前差距

1. 首页更像产品介绍，而不是每天打开就能使用的行动入口。
2. Deadline 虽有颜色和完成归档，但默认仍需要用户自己判断哪些最紧急。
3. Map 已有课程、章节、概念与 AI 笔记，但搜索结果过去主要依赖名称，案例正文不容易被找到。
4. 跨课程关系仍弱于成熟知识图谱；这是下一阶段问题，不应阻塞当前效率目标。

## V1.7 决策

1. 首页首屏回答“现在最需要关注什么”，显示未来 7 天 Deadline 和课程数量。
2. Deadline 默认展示逾期及未来 7 天，提供全部未完成、已完成和已归档筛选。
3. 有提交链接的任务从首页直接进入提交地址，减少一次跳转。
4. Map 搜索覆盖知识框架、案例、双语摘要和来源信息。
5. 收紧桌面与移动端的首屏高度、卡片尺寸和按钮层级。

## 暂不加入

- 没有稳定资料来源前，不做 AI 自动答题或自动生成大量知识卡片。
- 不增加付费云服务作为公开浏览和本地记录的前置条件。
- 不新增一级页面；Schedule 与 Map 仍是产品骨架。
